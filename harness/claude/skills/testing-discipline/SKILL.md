# Testing Discipline

- 실행 없는 검증은 검증이 아니다. 반드시 실제로 돌리고, 출력 원문을 산출물에 포함한다.
- 테스트는 격리 환경에서: section9 관련 작업은 `S9_ROOT=$(mktemp -d)` 로 라이브 데이터를 절대 오염시키지 않는다 (이 규칙은 실사고에서 나왔다).
- 케이스 설계: 정상 1 + 경계(빈/0/최대/유니코드) + 실패 경로(잘못된 입력이 올바르게 거부되는가) + 회귀(고친 버그 재현 케이스).
- 실패한 테스트가 성공한 테스트보다 가치 있다: 실패를 축소 재현(최소 입력)으로 좁혀 보고한다.
- flaky는 버그다: "다시 돌리니 됐다"로 닫지 말고 원인(타이밍/순서/상태 공유)을 기록.
- 결과 보고: 실행 명령, 환경, 통과/실패 수, 실패 상세, 정리(cleanup) 여부. 테스트 산출물은 반드시 정리.

## 임시상태 위생 (하네스 기본 — 반드시 지킬 것)

산출물(deliverable)을 제외한 임시파일·프로세스·상태는 작업이 끝나면 **모두 정리**한다. 좀비 프로세스·잔여 락·누적 임시파일을 남기지 않는다.

- **프로세스**: 테스트로 띄운 서버·데몬(`s9 serve` 등)은 반드시 종료한다. 백그라운드 작업은 완료/실패까지 추적하고 방치하지 않는다.
- **좁은 종료**: `pkill -f "s9 serve"` 같은 광범위 패턴 금지 — 사용자의 다른 서버를 죽인다. **PID·포트를 지정**해 해당 프로세스만 종료한다.
- **임시파일**: 고정 경로 금지. `mktemp`(고유명)로 만들고 끝나면 삭제한다. `S9_ROOT=$(mktemp -d)` 테스트 루트는 종료 시 `rm -rf`. `/tmp`·`/mnt/c/Temp` 등 모든 임시경로가 대상 — 무분별하게 파일 수를 늘리지 않는다.
- **잔여 락**: `.s9.lock`이 죽은 PID를 담고 있으면 s9가 자동 회수한다(acquire_lock). 수동 삭제 전 `cat .s9.lock`로 홀더 생존을 확인한다.
- 세션/턴을 마치기 전, 내가 띄운 프로세스·만든 임시파일이 남아있지 않은지 확인한다.
