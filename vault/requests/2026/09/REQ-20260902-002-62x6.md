### 결론 한 줄

**이 제품이 스스로 지은 말은 우리 말로 옮기고, 밖에서 빌려 온 명령·하위명령·
식별자는 빌려 온 글자 그대로 세운다.** 가르는 물음은 하나다 — **이 화면을 닫고
그 일을 하려면 사람이 무엇을 쳐야 하는가.** 칠 글자가 있으면(`git push`) 그
글자가 곧 화면의 낱말이고, 칠 글자가 없으면(승인·반려·이어가기·무인 작업)
우리 말이다.

### A. 옛 판정(2026-09-01 19:53)의 전제가 틀린 자리

옛 판정은 축을 **품사**로 잡았다 — "이름(명사)은 원어, 행위(동사)는 우리 말".
근거로 든 `card.js:1663-1670`(「이름은 이름처럼, 행위는 행위처럼」)은 옳았지만,
그 자가 왜 들었는지를 잘못 읽었다.

`done` 과 「승인」이 갈린 진짜 축은 품사가 아니라 **누가 그 말을 지었는가**였다.
`done` 도 「승인」도 **둘 다 이 제품의 말**이고, 그 닫힌 집합 안에서만 품사 자가
든다. 그 자를 집합 밖으로 들고 나간 것이 잘못이다: `push` 는 명사도 동사도
아니라 **명령 이름**이고, 명령 이름은 이름과 행위가 한 글자다. 품사 자를 대면
반드시 반으로 쪼개지고, 화면은 밖에서 안 통하는 반쪽을 세운다 — 「올리기」를
배운 사람이 GitHub 에 가면 `push` 를 다시 배워야 한다. 사전 두 벌이다.

되돌아보면 옛 판정 자신이 이미 답을 절반 적어 두고 지나쳤다: "다시 만나는 것이
판정을 바꾸는 이유는 *대조*가 필요해서다." 맞다. 그런데 대조가 필요한 것은
식별자만이 아니다 — 무엇을 **눌러야** 그 일이 되는지도 밖과 대조된다.

### B. 못 세 개 — 선이 흐려지는 자리

**못 1 — 개념 일반명사는 빌려 온 것이 아니다.** repository·history·working tree
는 아무도 치지 않는 개념이고 「저장소」·「이력」·「고치던 파일」이라는 확립된
우리말이 이미 있다(GitHub 한국어 화면도 「저장소」를 쓴다). 여기까지 로마자로
미는 것이 **무차별 원어**이고, 그것도 반려 사유다. `git worktree` 는 하위명령
이름이라 원어, `working tree`(두 낱말)는 개념이라 「고치던 파일」 — 이 갈림이
경계선의 실제 모양이다.

**못 2 — 이 제품이 지은 말은 그대로 둔다.** 「무인 작업」·「도는 일」·「담당」·
「이어가기」·「바로 보임/끝나면 보임」은 밖에서 다시 만날 원어가 없다.
`auto_resume` 은 이 제품의 config 키이지 남의 도구 이름이 아니다. 되돌리지 마라.

**못 3 — REQ-20260829-030-62x6 5차 반려와 부딪히지 않는다.** 그때 사용자는
「커밋하면 다시 워크트리로 간다」를 헤더에서 내리게 했다("사용자가 깃을 전혀
모르는 상태"). 두 판정은 **처방이 다를 뿐**이다.

- 030 의 처방: 읽어도 내가 할 일이 아닌 사실은 **화면에서 내린다.**
- 이번의 처방: 내릴 수 없는 자리(설정 스위치는 사람이 정해야 한다)에서는
  **원어로 이름을 대고 한 줄로 뜻을 붙인다**(writing-clarity: 처음 등장 시 정의).
- **틀린 처방**: 사실은 남겨 두고 우리가 지은 **별명**으로 부른다. 그것이

  여전히 못 읽고, 깃을 아는 사람은 `git worktree` 와 잇지 못한다.

### C. 판정표

원어 = 로마자 그대로 · 음차 = 「커밋」류 한글 소리 · 옮김 = 우리 말.

| 낱말 | 판정 | 근거 한 줄 |

| `pull` | **원어** (前 「받기」 폐기) | 화면을 닫으면 `git pull` 을 쳐야 한다 — 칠 글자가 곧 화면의 낱말. |
| `push` | **원어** (前 「올리기」 폐기) | 같은 이유. 단추 낱말이어도 원어로 선다(s9-design 6절 신설 조항). |
| `commit` | **원어** (前 음차 「커밋」 폐기) | 같은 이유. 음차는 원어와도 우리말과도 안 맞는 제3의 글자다. |
| `worktree` | **원어** (前 「따로 떼어 놓고 일하기」·음차 「워크트리」 폐기) | `git worktree`·`s9 worktree ls` 의 하위명령 이름. 別名 금지는 못 3. |
| `merge` / `rebase` | **원어** | 화면이 고르지 않으니 개념어로는 안 세우되, 터미널로 보내는 자리에서는 `git pull --rebase` 를 mono 로. |
| `branch` | **원어** (설 때만) | 이 판에 가지가 하나뿐이라 여전히 화면에 안 세운다. 서면 `branch` — 「가지」·「브랜치」 둘 다 기각. |
| `main` / `origin` / `upstream` / 짧은 해시 | **원어** (前 판정 유지) | 이름이다. remote 가 둘인 설치에서는 `origin`·`upstream` 을 이름 그대로. |
| `fetch` | **안 세움** (前 판정 유지) | 사람이 청하는 일이 아니라 화면이 셈을 얻는 방법. 「방금 확인」 + 「다시 확인」. |
| `ahead` / `behind` | **옮김 — 「`push` 할 것 N개」/「`pull` 할 것 N개」** | 단추 낱말과 같은 말이라 배울 것이 없다. 「앞선 것/뒤진 것」은 여전히 기각(대비쌍 — card.js:990 선례). |
| `working tree dirty` | **옮김 — 「고치던 파일 N개」** (前 판정 유지) | 두 낱말 개념이지 명령 이름이 아니다. 못 1. |
| `repository` | **옮김 — 「저장소」** (前 판정 유지) | 확립 번역어. 음차 「리포」도 기각 — 한 사물에 두 이름. |
| `remote` | **원어**(remote 가 둘일 때 이름으로) / 그 외 **안 세움** | 이 판에서 원격의 사용자쪽 이름은 이미 `GitHub` 이다(022 B-1). |
| `history` | **옮김 — 「이력」** | 개념. 못 1. |
| sync | **옮김 — 「동기화」** (settings.js:170 유지) | `git sync` 라는 명령은 없다. 여기까지 미는 것이 무차별 원어다. |
| SSE `push` | **원어** (前 음차 「푸시」 폐기) | git 의 push 는 아니나 남의 규격 이름인 것은 같다. |
| `GitHub` / `Claude` / `Monitor` | **원어, 본문 글자, 원 대소문자** | 제품 이름이다 — 치는 글자가 아니라 부르는 이름. 「깃헙」 기각(022 B-1). |
| `git` | **원어, 소문자, mono** | 명령 이름이다. |
| 「무인 작업」·「도는 일」·「담당」·「이어가기」 | **그대로 둠** | 밖에서 다시 만날 원어가 없다. 못 2 — 되돌리지 마라. |

### D. 표기 형식 (한 벌로 고정)

1. **로마자·소문자·원 표기 그대로. 음차 금지.** 음차는 어느 쪽 사전에도 없는
   제3의 글자라 대조가 반만 된다 — 대조가 이 낱말들이 화면에 서는 유일한 이유다.
2. **mono.** 선례는 `done`·`in-progress`(card.js `stName`). mono 는 "이것은 내가
   어딘가에 그대로 칠 글자다"를 형태로 말한다. 본문 글자로 세우면 문장에 녹아
   대조 신호가 죽는다.
   - **예외**: mono 를 못 넣는 자리(`workercfg.js` 의 `name`·`mean` 은 `esc()` 만
     받아 HTML 이 안 들어간다)에서는 **본문 글자로 서되 낱말은 그대로 둔다.**
     표기는 자리의 제약이고 낱말은 규칙이다 — "mono 를 못 쓰니 한국어로 옮기자"로
     가지 마라. 선례: 「내 GitHub 계정 쓰게 하기」도 본문 글자다.
3. **낫표(「」)를 겹치지 않는다.** 낫표는 **이 화면이 지은 이름**의 옷이다
   (「무인 작업」·「이어가기」). 남의 이름에 씌우면 두 어휘를 가르는 유일한 시각
   신호가 지워진다. `push` 는 mono 로만, 「무인 작업」은 낫표로만.
4. **조사** — 받침으로 갈리는 조사(은/는·이/가·을/를·으로/로)를 로마자 뒤에 바로
   붙이지 마라. `push` 는? `push` 은? 어느 쪽으로 통일해도 낱말마다 절반이 틀린다
   (card.js:1674 가 `done 으로`·`in-progress 로` 에서 이미 겪은 것).
   - 첫째 답: **`하다`·분류 명사를 끼운다** — `push` 하는 것도 / `commit` 하면 /
     `push` 할 것 3개 / `worktree` 자리.
   - 둘째 답: **갈리지 않는 조사만** — 도·에·에서·까지·만.
   - 그래도 붙여야 하면 **한 칸 띄우고 소리 나는 대로**: `worktree` 로 / `worktree` 를.
     띄어쓰기는 mono 와 한글이 엉키는 것을 막는다(이 저장소가 이미 쓰는 형식).
