### 2026-08-27T11:39:17+09:00 response (by sjpark1)

**세션이 스스로 첫 턴을 돈다.**

원인은 하나였고, 화면은 거짓말을 한 적이 없다. `claude` 는 대화형으로 뜨면
**첫 사용자 입력 전까지 한 턴도 돌지 않는다.** SessionStart 훅이 '수신함 tail 을
arm 하라'고 컨텍스트에 넣어 두어도 그 지시를 실행할 주체가 아직 안 깨어 있다.
그래서 `_inbox_watch_alive()` 가 false 였고, 터미널은 정직하게 `idle` 이라고 썼다.
사람이 아무 줄이나 한 번 치면 그제서야 tail 이 걸려 `live` 가 됐다 — '여태 그래
왔다'는 사용자의 관찰이 정확히 그 메커니즘이다.

**고침**: `s9 code` 가 claude 의 위치 인자로 기동 줄 하나(`[section9 bootstrap] …`)를
붙인다. 세션은 그 한 턴을 돌면서 tail 을 arm 하고 수신 대기가 된다. 그 줄은 사람이
친 말이 아니므로 audit 훅이 마커를 보고 **카드도 서문도 만들지 않는다** — 아니면
세션마다 유령 REQ 가 하나씩 쌓이고 첫 화면이 훅 텍스트로 덮인다.

사람이 자기 프롬프트를 주면(`s9 code '포트 봐줘'`) 기동 줄을 붙이지 않는다. 위치
인자가 둘이면 claude 가 받지 않고, 무엇보다 사람의 말이 우선이다. 플래그만 준
경우(`s9 code --permission-mode acceptEdits`)는 프롬프트가 없는 것이라 붙인다.

**검증**: tests/test_code_bootstrap.py 7건 (N1 기동 줄 부착 · N2 arm 지시 포함 ·
B1 사람 프롬프트 우선 · B2 플래그만이면 부착 · F1 카드 없음 · F2 감사 서문 없음 ·
R1 보통 프롬프트 회귀). 전체 스위트 847건 OK.

**남은 한계 (숨기지 않는다)**: 값을 안 받는 플래그 바로 뒤에 프롬프트를 붙이면
(`s9 code --verbose 안녕`) 그 프롬프트를 플래그 값으로 읽어 기동 줄이 함께 붙는다.
claude 의 플래그 사전을 여기 복제하는 값보다 이 한계를 적어 두는 값이 크다고 봤다.

**이번 세션에서 실증**: 이 요청을 조사하던 중 tail 을 arm 하자 대시보드가 즉시
`idle` → `live` 로 바뀌었다 (캡처: scratchpad/shots/live-now.png). 원인 진단이
맞았다는 증거다.
