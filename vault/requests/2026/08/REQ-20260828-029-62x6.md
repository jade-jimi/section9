**결론: 목록에 적을 것은 IANA 이름과 "지금 몇 시인가" 둘뿐이다. 한국어는 화면이 아니라 검색어 쪽에 둔다. 고르는 즉시 저장하고, 바뀐 것은 그 칸의 시계가 그 자리에서 증명한다.**

지금 결함은 라벨이 아니라 **입력 방식**이다. 이름을 외워서 쳐야 하고, 오타는 조용히 물러선다 — 화면은 `Asia/Seuol` 을 저장했다고 보여 주는데 시각은 시스템 로컬이다. 그 거짓말을 없애는 것이 이 작업의 본질이다.

칸 이름: `timezone` 유지(설명 줄에서 "시간대"). 근거 — 이 행이 속한 절 제목이 이미 `개인화 설정 — config/settings.json` 이라 표가 파일의 키를 가리킨다. 옆 행 digest_binder·skin·tone 도 같은 규칙. `타임존` 은 인용도 한국어도 아닌 음차라 쓰지 않는다. **뒤집히는 조건**: designer 가 이 행을 자기 절로 빼면 라벨은 `시간대` 가 되고 timezone 이 설명 줄로 내려간다(기록 남기기/stream_mirror 가 선례). 둘을 섞지는 마라 — 키 표 안에 한국어 라벨 하나만 두는 것이 제일 나쁘다.

목록: `Asia/Seoul   지금 17:02` 두 칸. 오프셋은 화면에서 빼고 검색어로만 받는다(손목시계에 +09:00 은 안 적혀 있다). 한국어 도시명 병기 안 함 — 498개 중 번역표가 있는 것은 30개 남짓이라 **목록의 절반만 한국어인 화면은 미완성으로 읽힌다.** 날짜가 다르면 `지금 어제 22:02`.
**왜 시각인가 (결정적 근거)**: `Etc/GMT+9` 는 POSIX 규약 탓에 실제로 **UTC−9** 다. 서울이 17:02 일 때 그것은 어제 23:02. 이름만 보면 한국인은 백이면 백 그걸 고른다. 시각을 옆에 두면 고르기 전에 틀린 것이 보인다.
처음 화면: `지금 쓰는 곳`(현재 값 + 설정 안 함) → `전체`(448개 알파벳순, 자르지 않고 이어 붙임). `Etc/*` 35개는 직접 칠 때만. `Factory`·`localtime` 은 어떤 검색어로도 내보내지 않는다.

검색어 — 맞춘다: seoul(대소문자 무시) · `new york`(공백↔`_` 정규화) · `asia/` · 서울·뉴욕·한국·일본(별칭표) · kst·jst·est(별칭표) · `+9`·`-5`(부호 있을 때만 오프셋). **별칭표는 보이지 않는 검색 키워드라 불완전해도 결함이 아니다** — 2번에서 한국어 병기를 뺀 대가를 여기서 치른다. 최소 50~60줄.
안 맞춘다(못 박음): 오타 교정 없음(시간대는 잘못 골라도 티가 안 나서 어림짐작이 정답처럼 보이는 것이 오타보다 위험하다) · 국가 코드 없음 · 부호 없는 숫자는 오프셋 아님 · 행정구역 없음 · 시각으로는 못 찾음.
주의: `kst` 를 계산으로 얻으려 하지 마라. Intl 은 미주·유럽엔 EST 를 주지만 아시아엔 GMT+9 를 준다 — 약어 검색은 계산으로 반쪽만 된다. 손으로 넣어라.

값이 비었을 때: 지금 `placeholder="Asia/Seoul"` 은 **거짓말에 가깝다** — 흐린 글씨가 설정된 것처럼 읽히는데 실제로는 시스템 로컬로 물러서 있다. 우연히 둘이 같아 아무도 몰랐을 뿐. `설정 안 함 / 이 컴퓨터의 시간대를 따릅니다` 로. 물러서는 대상은 브라우저가 아니라 **서버가 도는 컴퓨터**이므로, /api/whoami 가 서버의 실제 해석 값을 주기 전까지 그 이름을 적지 마라.

저장: 즉시 저장(같은 판의 다른 설정이 전부 그렇다). 알림 — `저장했습니다 — 이제 Asia/Seoul 기준입니다. 지금 17:02.` 조사 함정 때문에 `기준입니다` 로 명사를 끼워 조사를 흡수한다(판정 창이 `done 상태로 옮깁니다` 로 푼 것과 같은 수법). 실패하면 표시를 이전 값으로 되돌린다.
**알림이 약속할 수 있는 것은 이 칸의 시계까지다.** 대화 기록·터미널 시각은 서버 기동 시 1회 계산된 값을 쓰므로 따라오지 않는다 — "화면 시각이 따라갑니다" 라고 넓게 쓰면 거짓이 된다. 그 결함은 별건으로 뗀다(REQ-20260828-030).

### 화면 구조

`개인화 설정` 표에서 timezone 행을 뺐습니다. 이 칸은 이제 즉시 저장되고 설명 한 줄과 알림 줄을 가지므로, 임의 키/값 표 안의 한 행으로는 담기지 않습니다 — `대화 기록`·`비밀 키` 가 이미 같은 이유로 자기 절을 씁니다(ux-writer 가 적어 둔 "뒤집히는 조건"이 이것입니다). 그래서 라벨은 `시간대` 가 되고 `timezone` 은 설명 줄로 내려갔습니다.

    시간대
    문서와 기록의 시각을 이 시간대로 적습니다 — config/settings.json 의 timezone.
    이름을 쳐서 좁히고 골라 주세요. 고르면 바로 저장됩니다.
    [ Asia/Seoul                ▾ ]   지금 17:44
    저장했습니다 — 이제 Asia/Seoul 기준입니다. 지금 17:44.

목록 한 줄은 **이름과 지금 몇 시인가** 둘뿐입니다. 오프셋은 화면에서 빼고 검색어로만 받습니다. 처음 화면은 `지금 쓰는 곳`(현재 값 + 설정 안 함) → `전체 448개`(자르지 않음)입니다.

시각 어휘는 이 판의 것 그대로입니다: 이름은 식별자라 모노, 시각도 모노, 그룹은 헤어라인으로 가르고, **고른 줄은 색면이 아니라 잉크 inset 바 + 굵기**입니다. 라운드·그림자 없음, 색면 하이라이트·세로 띠 없음.

목록은 body 에 fixed 로 띄웁니다 — 설정 판은 안쪽 스크롤이 있고 glass 스킨은 .docs 를 잘라서, 판 안에 그리면 목록이 접힌 자리 아래로 숨습니다. ledger/calm, paper/carbon, normal/compact 조합에서 캡처로 확인했습니다.

### 지정한 함정 여섯 — 전부 처리

1. **`설정 저장` 버튼에서 timezone 제거.** 렌더 시점의 낡은 값이 방금 고른 값을 덮는 길을 끊었습니다. 옛 입력칸(`#cf-timezone`)도 없앴습니다.
2. **목록 출처는 서버.** 새 API `GET /api/timezones` 가 zoneinfo 목록을 냅니다 — `zones` 448개(훑는 목록) + `legacy` 48개(`Etc/*` 35 + `UTC`·`EST` 같은 호환용 13). 브라우저 `Intl.supportedValuesOf` 는 쓰지 않습니다. 응답에는 이름과 지금 오프셋(분)뿐이고 사용자 값은 실리지 않습니다.
3. **`Etc/*` 는 직접 칠 때만, `Factory`·`localtime` 은 어디에도 안 나옵니다.** 덤으로 `+9` 같은 오프셋 검색에서 호환용 이름을 아예 뺐습니다 — 이름에 `+9` 가 박힌 `Etc/GMT+9`(실제 UTC−9)가 `+9` 검색의 맨 위로 올라오면 그게 곧 함정이라서입니다. 그 이름은 `gmt+9` 를 직접 칠 때만 나오고, 그때 옆에 `지금 어제 23:25` 가 붙습니다(두 번째 그림).
4. **저장 실패 시 표시를 이전 값으로 되돌립니다.** 손 없이 눌러 확인했습니다(네 번째 그림) — 서버가 모르는 이름을 거절하자 칸이 이전 값으로 돌아왔습니다.
5. **시계 30초, `document.hidden` 이면 정지, 판이 사라지면 타이머 정리.** 화면으로 돌아오면 30초를 기다리지 않고 그 자리에서 갱신합니다.
6. **`placeholder="Asia/Seoul"` → `설정 안 함`.** 물러서는 곳은 `이 컴퓨터의 시간대를 따릅니다` 로만 적었고 서버가 해석한 이름은 적지 않았습니다(세 번째 그림).

### 덤으로 막은 것

지금까지 `s9 user config <이름> timezone Asia/Seuol` 은 **조용히 저장됐고** 시각만 시스템 로컬로 물러섰습니다. 화면이 거짓말을 하던 그 원인이라 `do_user_config_set` 에서 거절하게 했습니다 — 목록을 만드는 판정(`zoneinfo.ZoneInfo`)과 같은 것입니다. 이미 그런 값이 저장돼 있는 계정은 칸 옆에 `이 이름을 모릅니다 — 지금은 이 컴퓨터의 시간대로 적힙니다` 가 뜹니다.
