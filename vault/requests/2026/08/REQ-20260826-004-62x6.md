## Original

docs탭의 좌측 문서 목록이 스크롤이 되지 않는다

## Notes

### 2026-08-26T02:34:29+09:00 designer (by nicehugepark)

원인은 sticky 타입바가 아니라 calm 스킨의 `overflow:hidden` 이었다.

### 원인
사용자 설정이 `ui_skin=calm` (users/sjpark1/config/settings.json) 이다. calm 재설계(647ad22) 때
목록 카드의 라운드 모서리를 자르려고 `[data-skin="calm"] .doclist{...overflow:hidden}` 을 넣었는데,
이 한 줄이 베이스의 `overflow-y:auto` 를 통째로 덮어 세로 스크롤까지 죽였다. 084(타입바)는 무관하다 —
084 이전부터 안 됐고, 다만 Board에서 knowledge/session 컬럼이 빠지면서 Docs 목록을 실제로 쓰게 되어
그때 드러났다.

측정 근거(수정 전, calm/graphite/1440x900): `.doclist` client=750 · scroll=2673 인데 computed
`overflow-y: hidden`. 내용은 750px 창에 2673px — 아래 1900px 넘게 있는데 휠로도 스크롤바로도 닿을 수 없었다.
같은 조건에서 ledger 는 `overflow-y: auto` 로 정상이었다(스킨 한정 결함).

### 두 번째 결함 (같이 고쳤다)
`.doclist`·`.viewer` 의 `max-height:calc(100vh - 150px)` 에서 150px 는 ledger 헤더 기준 매직 상수다.
calm 은 헤더가 더 높아(top=153) 판 아래쪽 3px 이 화면 밖으로 나갔고, 1100px 폭에서 필터가 줄바꿈되면
top=192 까지 올라가 42px 이 잘렸다 — "끝까지 못 본다"가 여기서도 났다.

### 수정 (web/index.html 한 파일)
1. `[data-skin="calm"] .doclist` : `overflow:hidden` → `overflow-x:hidden; overflow-y:auto`.
   가로만 자르면 라운드 클리핑은 그대로 유지되고 세로는 흐른다. 스크롤 컨테이너는 어차피
   padding box 에서 자르므로 모서리도 깨지지 않는다.
2. `.doclist`·`.viewer` 의 max-height 를 `var(--docsh, calc(100vh - 150px))` 로. 상수는 폴백으로만 남긴다.
3. `sizeDocs()` 추가 — `.docs` 의 실제 시작 위치와 main 의 하단 패딩을 실측해 `--docsh` 를 넣는다.
   renderDocs 직후 + requestAnimationFrame, window resize(60ms 디바운스), 그리고 header 에 건
   ResizeObserver 에서 다시 잰다. 헤더는 사용량 줄이 비동기로 붙거나 필터가 줄바꿈되며 로드 후에도 자란다.
   Stream 탭의 `.streamwrap .doclist` 는 `.docs` 밖이라 폴백 상수를 그대로 쓴다 — 동작 변화 없음.

### 대안 비교
(가) calm 에서 overflow:hidden 을 지우기만 — 라운드 모서리 밖으로 행이 삐져나온다. 기각.
(나) 목록 안쪽에 래퍼를 하나 더 넣어 바깥은 클립, 안쪽은 스크롤 — DOM 한 겹과 sticky 기준이 늘어난다.
    같은 결과를 CSS 한 줄로 얻을 수 있어 기각.
(다) 채택 — 축별 overflow. 되돌리기 비용이 한 줄이고 다른 스킨에 영향이 0이다.
높이 쪽: (가) calm 전용 상수(예: 176px) 추가 — 스킨·밀도마다 상수가 늘어난다. 기각.
(나) body flex column 으로 셸을 재구성 — 정답이지만 Board·Graph 의 페이지 스크롤까지 건드린다. 이 결함에 비해 과하다. 기각.
(다) 채택 — 실측 1회 + 헤더 변화 관측. Docs 판에만 닿는다.
