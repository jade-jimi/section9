## Notes

### 2026-08-29T00:58:17+09:00 response (by nicehugepark)

원인 확정: 부트마다 /tmp 를 통째로 지우는 비용이다.

증거 넷.
(1) 유닛 명령이 'systemd-tmpfiles --create --remove --boot --exclude-prefix=/dev' 이고, --remove 가 붙으면 tmp.conf 의 'D /tmp 1777 root root 30d' 가 /tmp 의 내용물 전체 삭제로 바뀐다. 전체 설정(/run·/usr/lib tmpfiles.d 15개 파일)에서 크기가 무한정 커질 수 있는 줄은 이 한 줄뿐이다 — 나머지는 /run·/dev·/etc·/var/log 로 전부 유계다.
(2) 같은 설정을 --remove 없이 돌리면 6ms 에 끝난다(사용자 권한, 244줄 debug 전부 수행). 시간은 만들기가 아니라 지우기에 있다.
(3) systemd 가 직접 잰 값: 'systemd-tmpfiles-setup.service: Consumed 14.098s CPU time.' — 벽시계 46초 중 14초가 CPU다. 한 곳에서 막힌 게 아니라 syscall 을 수십만 번 친 모양이다.
(4) /tmp 디렉터리 아이노드 자체가 7,860,224 바이트다(/var/tmp 는 4,096). ext4 디렉터리는 한 번 커지면 줄지 않으므로, /tmp 가 10만 개대의 엔트리를 담았던 적이 있다는 뜻이다.

기여 요인 — 우리 테스트가 /tmp 를 흘린다: tests/*.py 84개가 tempfile.mkdtemp 로 S9_ROOT 를 만들고 rmtree 를 한 번도 하지 않는다(정리 코드 없음 확인). 한 번 돌 때마다 vault 한 벌씩 84개가 /tmp 에 남는다. 지금 이 순간에도 /tmp/s9gate-* 가 분당 1~2개씩 쌓이는 중이다(00:47 13개 → 01:05 20개).

파급: sysinit.target 이 그만큼 늦어 systemd-logind 가 73초 뒤에 뜨고, WSL 의 10초 창(CreateLoginSession)을 놓쳐 REQ-002 의 '사용자 세션 실패' 메시지가 난다. 두 건은 같은 뿌리다.

남는 조치(별건 후보): tests 의 mkdtemp 를 addClassCleanup/rmtree 로 회수한다. systemd 를 끄면 부트 비용은 사라지지만 /tmp 누수 자체는 남는다.
