**검증된 모순** — 터미널 쪽 신원은 원래부터 파생입니다(세션 바인딩 → 환경변수 → OS 계정 순으로 자동 결정, 아무도 고르지 않음). 대시보드만 예외적으로 "자기신고 셀렉터"를 요구해 왔는데, 대시보드는 127.0.0.1 전용이라 **브라우저 앞의 사람 = 이 머신의 OS 계정 = 서버를 띄운 계정**입니다. 서버는 그 계정명과 hostname을 이미 알고 있습니다. 즉 me 박스는 서버가 아는 사실을 사람에게 되묻는 UI였습니다.

**제안 — whoami 모델(선택 → 파생)**:
- 서버가 기동 시 OS 계정을 s9 프로필과 매칭해 신원을 확정하고, 대시보드는 **표시 전용 라벨** `nicehugepark @ DESKTOP-TEHV1KR [admin]`만 보여줍니다. 셀렉터와 localStorage 저장은 폐기.
- 조작 주체(actor)도 클라이언트가 보내는 값 대신 **서버가 파생** — 자기신고 스푸핑 표면 자체가 줄어듭니다(단, 실인증은 여전히 아니라는 경계는 유지).
- 격리·개인화는 그대로 whoami 기준으로 동작합니다.

**실패 모드까지 검토했습니다**: ① 미등록 OS 계정 → 등록 안내 배너, ② **로밍(머신마다 OS 계정명이 다른 경우)** → 새 머신에서 1회 `s9 user attach`로 별칭 연결하면 이후 자동(선택 UI가 아니라 1회 CLI), ③ 한 OS 계정을 여럿이 공유하는 예외만 admin 전용 "대리 조작"을 Settings 안에 숨겨 제공, ④ 대시보드를 외부에 여는 순간은 whoami도 무력 — 실인증 필수라는 기존 결론 유지.

review 카드(REQ-025)에서 판정해 주십시오: 셀렉터 폐기 + attach 방식 로밍에 동의하시면 구현(서버 whoami·actor 파생·UI 라벨·가이드 개정, M 규모)으로 넘어갑니다. 현재 review 대기: 018(가이드 재판정)·019(에셋 체계)·025(신원 파생) 세 건입니다.
