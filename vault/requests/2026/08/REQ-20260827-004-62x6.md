## Notes

### 2026-08-27T00:13:45+09:00 response (by sjpark1)

REQ-20260826-041-62x6 을 닫으면서 "같은 함정이 다른 명령에도 있을 수 있다"를 남은 위험으로 적었다. 전수로 훑고 **실제로 눌러서** 확인했다 — 정적 조사만으로는 후보가 8개였는데, 돌려 보니 진짜는 2개였다.

**함정의 정확한 조건**은 "옵션 뒤 위치 인자"가 아니었다. argparse 는 **필수** 위치 인자는 옵션 건너 뒤에서도 붙여 준다(`s9 status <id> --note X in-progress` 는 멀쩡히 된다). 죽는 것은 **선택적 위치 인자(`nargs="?"`/`"*"`)가 값 받는 옵션 뒤에 올 때**다 — argparse 가 그 자리에서 "없음"으로 만족시켜 버리고, 뒤에 온 실제 값이 미아가 된다.

**실제로 죽는 것 둘** (직접 실행해 확인):

    s9 resume --model m <SID> "이어서 해"
      → s9: error: unrecognized arguments: --model 이어서 해
    s9 user --json config tester
      → s9: error: unrecognized arguments: --json

**멀쩡한 것들**: `status` · `bind` · `snapshot` · `instance` · `project` — 정적 조사에서는 후보였지만 실제로는 붙는다. 조건이 위와 같기 때문이다.

`resume` 이 특히 나쁘다. 무인 재개 경로라 **사람이 결과를 안 보는 자리**이고, 041 에서 배운 그대로 실패 메시지가 입력을 되비추므로 로그만 봐서는 성공과 구분되지 않는다.

**요구**: `resume`·`user` 를 041 과 같은 방식(argparse 이전 인자 정규화)으로 막는다. 그리고 이번처럼 **새 서브명령을 추가할 때 이 조건이 다시 생기지 않도록** 계약 테스트로 박는다 — 파서를 훑어 "값 받는 옵션 + 선택적 후행 위치 인자" 조합이 정규화 목록에 없으면 실패하게. 사람이 매번 기억할 일이 아니다.
