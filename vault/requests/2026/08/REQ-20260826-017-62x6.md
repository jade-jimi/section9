3. 답의 소유: 질문 문서에 답을 노트로 붙인다(응답이 곧 문서 본문). 답이 없는 질문 문서는 "미답" 상태로 보인다 — 지금은 답을 안 해도 아무 흔적이 없다.

### 결정 세 가지 (근거 전문 DOC-20260826-011-62x6)

**1. 무엇이 질문 문서가 되는가 — 훅이 사전에, 20자 기준으로. 답은 자동으로 붙는다.**

유실이었다. 훅은 매 프롬프트 무조건 도는 보장된 경로다.
남길 가치는 답이 나온 뒤에야 확정되므로 사전 판정은 근사임을 인정하고, 오분류는 양방향
정정 경로로 푼다(불필요하면 `s9 rm`, 누락됐으면 `s9 new question` — 주입 문구에 명시).

핵심은 **답이 자동으로 붙는다**는 것이다. 지금 질문 턴은 `s9 last --pause` 로 응답 캡처를
꺼서 답이 어디에도 안 남았다. 새 경로: 프롬프트 훅이 `bind last_qst <QST>` 를 세우고,
Stop 훅이 **last_req 가 빈 턴에서만** 그 포인터로 폴백해 `--label answer` 로 기록한다.
`last_req` 는 건드리지 않는다(위임 캡처·스트림 활성 판정이 걸려 있다 — REQ-20260823-072).
Request 턴 동작은 한 줄도 바뀌지 않고, **사람에게 새 규율을 요구하지 않는다.**

**2. knowledge 와의 구분 — 질문은 사건, 지식은 규칙. 승격은 한 방향.**
QST = 그때 무엇을 묻고 무엇이라 답했나(시점 고정, 개정하지 않음). DOC = 앞으로 무엇을
그렇게 해야 하나(시점에서 분리, 개정됨). 판정 질문 하나: **그 답이 다음 작업을 구속하는가.**
아니오면 QST 에서 끝, 예면 `s9 new knowledge` + `s9 link <DOC> --derived-from <QST>`.
승격 후에도 **규칙 전문을 QST 에 복사하지 않는다** — 사건은 QST 한 곳, 규칙은 DOC 한 곳,
