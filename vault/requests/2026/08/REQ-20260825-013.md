재검토(반려 반영) — "vault/assets에 모으면 다른 프로젝트에서 올린 이미지도 다 보이는 것 아닌가?"에 대한 입체 분석.

### 0. 직접 답

"보이느냐"는 저장 경로가 아니라 **어느 계층에서 보느냐**로 갈린다. 첨부의 노출 면은 3계층이고, 원칙은 '첨부=문서의 일부 → 각 계층에서 소유 문서와 정확히 같은 노출 수준'이다. 결론부터: **대시보드에서는 다른 프로젝트 첨부가 보이지 않도록 설계돼 있고(비멤버=404), git 계층의 프로젝트 간 노출은 첨부 경로가 아니라 동기화 리포 구성(REQ-048)이 결정한다.**

### 1. 노출 3계층 분석

**① 대시보드 열람 — 격리됨(안 보인다).** 문서 열람은 doc_visible 가드레일(REQ-20260824-017)을 응답 직전에 적용한다: admin 전부 / 프로젝트 문서는 활성 멤버만 / 무프로젝트 문서는 작성자만, 비가시는 404로 존재 자체를 누설하지 않는다. 신설할 첨부 서빙 라우트는 **소유 문서의 doc_visible을 그대로 적용**하므로 비멤버에게 타 프로젝트 첨부는 404다. 이 판정이 가능하려면 파일이 문서 ID에 키잉돼 있어야 하는데, 제안 구조(…/<DOC-ID>/…)가 바로 그 장치다. 반대로 **현행 uploads/(전역 디렉토리+시간스탬프)는 '이 파일의 소유 문서'를 알 수 없어 프로젝트별 격리 판정 자체가 불가능**하다 — 즉 제안 구조가 격리를 만들고, 현행 구조가 격리를 막는다. 참고: 현재는 첨부 서빙 라우트 자체가 없어 대시보드로는 어떤 업로드 이미지도 보이지 않는다(/uploads/ 접근 404 실측, 2026-08-25). 세션(Claude)이 파일시스템 Read로만 소비한다.

**② git/동기화 — 리포 접근권자는 전부 본다. 단 이는 첨부만이 아니라 문서 본문도 동일하다.** 현재 vault/는 .gitignore(REQ-20260824-046)라 커밋 자체가 안 되므로 지금은 문서도 첨부도 리포에 실리지 않는다. 동기화 도입 시(REQ-048 / DOC-20260824-002: 사설 vault 리포) 그 리포를 클론하는 사람은 모든 프로젝트의 문서+첨부를 파일로 본다. doc_visible은 자기신고 기반 가드레일이지 인증이 아니다(DOC-20260823-001 명시). **프로젝트 간 '비밀'이 실제 요구라면 경계는 리포 단위(프로젝트별 사설 리포 분리)여야 하며, 이는 REQ-048의 판정 사항**이다. 첨부를 DOC-ID로 키잉해 두면 catalog의 문서→프로젝트 매핑으로 첨부까지 함께 분리 이전할 수 있어 단일 리포/분리 리포 어느 갈림길과도 호환된다.

**③ 파일시스템 — 같은 머신·OS 계정 접근자는 vault 전체를 직접 읽을 수 있다.** 문서와 동일한 명시적 한계(로컬 파일 원칙, DOC-20260823-001).

### 2. 차원별 점검

- **기능**: 업로드(직후엔 REQ id 미정 → state 임시 저장 → chat audit가 REQ 확정 시 이동), 채팅 표시(파일명 칩만 — 이미지 바이트 서빙 없음, REQ-012), 문서 열람(/api/doc + doc_visible), 신설 첨부 라우트(동일 필터 + DOC-ID·safe_name 검증으로 경로 순회 차단, 디렉토리 리스팅 없음, 비가시=404 동일 응답), 삭제(현행 s9 rm은 md만 지움 → 첨부 디렉토리 동반 정리 필요), 마이그레이션(uploads 잔존 5파일을 참조 문서로 매핑해 1회 이전).
- **사용자**: admin(전부) / 프로젝트 멤버(문서=첨부 동일) / 비멤버(404, 존재 미누설) / 미등록 뷰어(비강제 부트스트랩 — 문서와 동일 원칙) / 무프로젝트 문서(작성자만).
- **프로젝트**: 경로에 project 세그먼트를 넣지 않는 이유 — (a) 문서 자체가 vault/requests/YYYY/MM에 전 프로젝트 혼재 저장이고 가시성은 메타(project)로 판정: 구조 대칭. (b) 문서의 project는 재지정될 수 있다 — 경로에 project가 있으면 재지정 때 파일 이동+본문 경로 재작성이 필요하고, DOC-ID 키잉이면 메타만 바뀌어 가시성이 자동 추종. (c) 무프로젝트 문서 존재. 프로젝트별 물리 분리가 필요해지는 시점(리포 분리 결정)에는 catalog 매핑으로 문서와 함께 이전하면 된다.
- **머신/계정**: 본문에 상대경로 기록 → 절대경로(/home/sjpark1/…)가 타 머신·타 계정에서 무효인 문제 해소.
- **용량/집중**: DOC-ID 하위 분산으로 원안 지적(단일 디렉토리 집중·파일명 충돌) 해소, YYYY/MM 파티션으로 비대화 완화(문서와 동일), 10MB 한도 유지·대형 파일 링크 권장.

### 3. 설계 확정안 (A′ — A안 경로만 수정)
