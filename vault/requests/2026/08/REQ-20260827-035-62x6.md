`cat ~/…/secrets/X` 를 실행할 수 있는 주체가 곧 나다. 파일 권한으로도 못 막는다 —
읽는 프로세스가 같은 사용자이기 때문이다. "모델은 못 본다"고 적어 두면 그건 거짓말이
되고, 거짓 안전은 없는 안전보다 나쁘다.

**진짜 경계를 원한다면** 값이 이 세션이 읽을 수 없는 곳에 있어야 한다 — 다른 OS
계정이 소유한 파일 + 그 계정으로 도는 중개 프로세스, 또는 OS 키체인 + 브로커. 그건
section9 밖의 구조 변경이라 별건이다.

**대신 확실히 줄일 수 있는 것 — 사고로 새는 경로 전부**

    1. 커밋   users/ 는 공개 업스트림에서 이미 제외. **인스턴스 리포는 users/ 를
              track 하므로 거기에 users/*/secrets/ 를 명시해야 한다** — 지금은
              빠져 있어서, 인스턴스를 만드는 순간 비밀이 올라간다. (사용자가
              "실수라도 커밋되지 않도록"이라고 한 그 자리다.)
    2. 목록   `s9 secret ls` 는 **키만** 낸다. 값은 절대 안 찍는다.
    3. 입력   값은 stdin 으로 받는다. argv 로 받으면 `ps` 와 세션 기록에 남는다.
    4. 사용   `s9 secret run -- <명령>` 이 `{{secret:KEY}}` 를 실행 시점에 바꾸고,
              **출력에서 그 값을 지운 뒤** 돌려준다. 모델은 자리표시자만 쓴다.
    5. 유출   가드가 스테이지된 내용에서 알려진 비밀값을 찾으면 커밋을 막는다.

**정직한 요약**: 사고로 새는 길은 막는다. **작정하고 읽는 세션은 못 막는다.**
그 구분을 문서와 명령 안내에 그대로 적는다.

**설계 결정 둘**

  바깥은 "리포에 두기 싫은 것"의 자리다.
- 저장 모양: 키 하나 = 파일 하나. 한 파일에 몰아넣으면 부분 유출이 전체 유출이 되고,
  diff·권한·삭제가 전부 거칠어진다.

### 2026-08-27T18:36:27+09:00 response (by sjpark1)

**보관·차단은 만들었다. "모델에게 안 보인다"는 약속하지 않는다.**

    s9 secret set <키>          값은 stdin 으로만 (argv 는 ps·세션 기록에 남는다) · 권한 0600
    s9 secret ls                키만 표시 · internal/external 표시 · 값은 어디에도 안 찍는다
    s9 secret get <키>          값 출력 (명령 치환용)
    s9 secret rm <키>           internal 에서 삭제
    s9 secret run -- <명령>      {{secret:키}} 를 실행 시점에 치환, 출력에서 값 제거

- **internal** `users/<이름>/secrets/` · **external** 설정의 `external_secrets_path`(리포 밖).
  같은 키가 양쪽에 있으면 internal 이 이긴다. 외부 경로가 없거나 못 읽어도 내부는 그대로 동작한다.
- **키 하나 = 파일 하나.** 한 파일에 몰면 부분 유출이 전체 유출이 되고 권한·삭제·감사가 거칠어진다.
- 키 이름은 파일명이 되므로 경로 탈출(`../`)·구분자를 거부한다.

**커밋 차단** — 경로만 보지 않는다. **값만 다른 파일에 붙여 넣는 것이 실제 유출 경로**라
스테이지된 내용에서 값 자체를 찾는다. 8자 미만은 흔한 글자와 부딪혀 오탐이 더 해로우므로
내용 검사에서 뺀다. 판정은 `secret_leak` 한 곳에 있다 — 가드와 CLI 가 각자 알면 한쪽만 고쳐진다.

**인스턴스 ignore 에 `users/*/secrets/` 를 넣었다.** 인스턴스 리포는 `users/` 를 track 하므로
없었으면 **사설 리포를 만드는 순간 비밀이 올라갔다.** 사용자가 "실수라도 커밋되지 않도록"이라고
한 그 자리다.

**약속하지 않는 것 (다시 적는다)**: 이 세션의 모델은 사용자와 같은 OS 계정으로 셸을 돈다 —
`cat` 을 실행할 수 있는 주체가 곧 모델이다. **"모델은 값을 못 본다"는 이 하네스 안에서
보장할 수 없다.** 적어 두면 거짓말이 되고, 거짓 안전은 없는 안전보다 나쁘다. 진짜 경계는
다른 OS 계정 + 중개 프로세스나 키체인 브로커처럼 section9 밖의 구조가 필요하다.
막은 것은 **사고로 새는 길** — 목록·argv·명령 출력·커밋 전부다.
