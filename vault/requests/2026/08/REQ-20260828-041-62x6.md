### ② 깨우기: `POST /api/wake`

요청 `{"id": "REQ-…"}` (as= 대리는 기존 규칙대로). 응답은 200(ok) / 409(거부),
본문 계약은 넷뿐이다:

    {"ok": bool, "id": str, "mins": int|null, "action": str, "message": str}

action: `spawned`(띄웠다) · `busy`(누가 붙어 있다) · `moving`(아직 조용하지 않다) ·
`capped`(한도/쿨다운) · `off`(계정 옵트인 꺼짐) · `disabled`(킬스위치) ·
`elsewhere`(다른 머신) · `no-cli` · `error` · `missing` · `not-request` · `not-in-progress`.

`message` 는 그대로 화면에 띄워도 되는 사람 말이다. 예:
- "REQ-… 를 깨웠다 — 무인 작업자가 이어받는다. 진행은 카드의 점과 Stream 에서 보인다."
- "이미 designer 가 붙어 있다 (3분 전 움직였다 · 코드 경로를 눌러서 본다). 겹쳐 띄우면 같은 파일에 두 번째 손이 붙는다."
- "오늘 무인 작업자 한도를 다 썼다 (20/20건) — 내일 0시에 풀린다. 지금 올리려면 계정 설정의 auto_resume_global_per_day 를 늘려라"
- "아직 멈춘 게 아니다 — 4분 전 문서가 움직였다. 15분 넘게 조용할 때만 깨운다."

지킨 것:
- **겹쳐 띄우지 않는다.** 깨우기는 화면·CLI 와 **같은 판정**(`stall_mins`)을 지난다 —
  화면이 '멈춤' 이라 그린 카드만 깨울 수 있다. ①에서 고친 위임 귀속이 그 입력이다.

- **킬스위치를 `_spawn_worker` 안으로 옮겼다.** 종전엔 호출부에만 있어 새 경로를 여는
  사람이 옮겨 적는 것을 잊으면 옆문이 났다. 이제 모든 스폰 경로가 그 앞을 지난다.
- **막힌 이유가 응답에 그대로 실린다.** `_auto_cap_block()` 이 캡 판정을 사람 말 사유로
  돌려주고(문턱 수치는 여전히 한 곳에만), `_spawn_worker(out=…)` 가 그것을 밖으로 낸다.

### 결정: 깨우기는 **스폰만** 한다 — '상태 되돌리기'는 내지 않았다

멈춤 줄이 붙은 카드에만 `깨우기` 버튼이 선다 → `POST /api/wake` → 서버가 준 `message` 를 **그대로** 창에 띄운다. 문서 화면도 **같은 함수**(`stallHTML`)가 그린다 — 갈라질 자리가 없다.

**화면이 읽는 필드는 `ok` 와 `message` 둘뿐이다.** `action` 값(spawned·busy·capped…)은 코드 어디에도 없다 — 알기 시작하면 같은 말이 서버와 화면 두 벌이 된다. 테스트가 그 낱말들의 부재를 잠근다.

**`ok=false` 는 실패의 옷을 입지 않는다.** `s9dlg` 의 눈썹 잉크가 종전엔 "알림이면 무조건 빨강"이었다. 근거를 `kind` 가 아니라 `stop` 플래그로 바꿨다(기본값은 종전 그대로). 깨우기의 거절은 `stop:false`, 서버에 못 닿은 것만 붉다.

### 자리 — 대안 비교

| | 결정 |
|---|---|
| **채택** 멈춤 줄 **아래** 행동 줄 (`.acts`+`.deed`) | 판정 카드가 이미 쓰는 순서(사실 → 행동). 새 컴포넌트 0 → 스킨 10벌이 손대지 않고 따라온다 (실측 확인) |
| 기각 줄 안 인라인 | 그 줄은 `nowrap`+말줄임이라 긴 문장과 버튼이 폭을 다투고, calm 에서는 3줄 클램프 안에 버튼이 갇힌다 |
| 기각 hover 시에만 | 가장 조밀하지만 키보드·터치에서 존재를 알 수 없다 |

결과 표시도 같은 식으로 갈랐다: **창 하나로 답한다**(성공·거절 동일). 카드 안 결과 줄은 폴링 재렌더에 증발하고, 한도 소진 문구는 카드 폭에 안 들어간다. 토스트는 이 화면에 없는 어휘라 판정 창과 둘이 된다.

### 덤으로 잡은 결함

**카드 안의 진짜 버튼이 Enter 를 빼앗기고 있었다.** `role="button"` 을 Enter 로 누르는 전역 핸들러가 `closest()` 로 판(카드)을 집어 올려, 버튼의 네이티브 활성화를 `preventDefault` 로 막고 카드를 눌렀다 — **마우스로는 깨우기가, 키보드로는 문서 열기가** 일어났다. 승인·반려·이어 말하기도 같이 앓고 있었다. 한 줄(`if (t.closest("button,a[href],summary")) return;`)로 고쳤고 넷 다 함께 나았다.

### 검증 — 전부 실제로 눌렀다

격리 서버(임시 `S9_ROOT`, 무인 작업자는 대역 스크립트)에 멈춘 요청을 세우고 Windows Chrome 을 CDP 로 몰아 실제 마우스 이벤트로 눌렀다. 응답은 전부 진짜 서버가 준 것이다.

- **성공**(`spawned`) — 스폰 로그에 `SPAWN(fresh) … reason=wake`. 카드가 그 자리에서 멈춤 줄을 잃고 점이 앰버로, 열 머리 `멈춤 3 → 2`
- **거부·이미 붙어 있음**(`busy`) — 화면이 카드를 그린 뒤 서브에이전트가 붙는 실제 경쟁을 만들어 눌렀다
- **거부·한도 소진**(`capped`) — 전역 카운터를 20/20 으로 채운 뒤
- **거부·아직 안 멈춤**(`moving`) — 화면이 그린 뒤 문서가 움직인 경쟁
- 도는 중(`깨우는 중…` 잠김) · 서버 끊김(붉은 `연결` 창 + 버튼 재활성) · 키보드(Tab 2회 → 포커스 링 → Enter) · 스킨 10벌 + compact + 어두운 톤 + 문서 화면 3벌
