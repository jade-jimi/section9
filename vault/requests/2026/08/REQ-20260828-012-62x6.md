볼 수 없던 이유는 단순하다 — **화면이 없었다.** REQ-20260827-035 는 CLI 만 만들고 done 이 됐고, web/index.html 에 "secret" 이라는 낱말은 한 번도 나오지 않는다. 이 사용자는 대시보드로 일한다. 거기서 보이지 않으면 없는 기능이다.

서버 쪽은 열었다(커밋 예정):
- `GET /api/secrets` — 키 목록과 어느 쪽(internal/external)인지. **값도 경로도 주지 않는다.**
- `POST /api/secret/set` — {key, value}. 값은 응답·로그·오류 문구 어디에도 남기지 않는다. 0700/0600.
- `POST /api/secret/rm` — {key}.

화면이 남았다.

**개인설정 → 내 계정 판에 자리를 냈습니다. 값은 화면 어디에도 나오지 않습니다.**

Settings → 내 계정, 개인화 설정 아래에 "비밀 키" 칸이 생겼습니다. 보이는 것은 **키 이름과 어디에 두었는지** 둘뿐이고, 값을 그리는 자리는 아예 없습니다.

**넣기.** 키 이름과 값을 적고 "＋ 넣기"를 누릅니다. 값 칸은 가려진 칸(password)이고, 저장하면 **성공이든 실패든 즉시 비웁니다** — 실패했다고 남겨 두면 그대로 방치되고, 화면에 남은 값은 캡처·화면 공유·어깨너머로 그대로 따라갑니다. 그래서 "값은 다시 보이지 않습니다"라고 저장 직후에 미리 말해 둡니다. 잊었으면 새 값으로 덮어쓰면 됩니다.

**지우기.** 되돌릴 수 없으므로 확인 창을 한 단계 둡니다. 이 제품은 파괴적 행동에 확인 대신 되돌리기를 주는 것이 원칙인데, 여기는 값이 어디에도 남지 않아 되돌릴 방법 자체가 없습니다 — 확인 창이 맞는 자리입니다. 창에는 "이 키를 쓰는 도구는 다음 실행부터 멈춥니다"까지 적었습니다.

**남의 계정 판에는 내지 않습니다.** 서버의 목록은 admin 대리(as)를 받지 않는데 넣고 지우는 쪽은 받습니다. 그대로 두면 admin 이 다른 사람 시점으로 볼 때 **남의 이름표 밑에 내 키 목록**이 뜨고, 거기서 넣으면 남의 저장소로 갑니다. 그 화면은 거짓말이므로 자리를 내지 않았습니다.

**상태를 다 그렸습니다.** 불러오는 중 · 아직 없음 · 받아오기 실패(다시 불러오기 손잡이). 빈 상태는 위 설명과 같은 회색으로 이어 붙지 않게 헤어라인으로 갈랐습니다.

**색면·세로 띠 없습니다.** 목록은 옆의 머신 이력 표와 같은 어휘입니다 — 모노, 헤어라인 행 구분. 어느 쪽에 있는지는 색이 아니라 낱말("저장소 안 / 저장소 밖")로 말합니다. 지우기 버튼은 평소 흐린 잉크로 물러나 있다가 손이 닿으면 경고색 글자·테두리로 얼굴을 바꿉니다.

### 검증 — 헤드리스에서 실제로 넣고 지워 봤습니다
