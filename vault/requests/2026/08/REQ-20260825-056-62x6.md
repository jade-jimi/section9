구조적 한계 5가지, 코드 근거와 함께:

1. **hex 문자열 `<...>` 미처리** — 2837행 정규식이 `rb"\((?:\\.|[^\\()])*\)"` 뿐. **한글 PDF는 사실상 전부 `Identity-H` + hex 문자열이므로, Word/Chrome/한글이 출력한 한국어 PDF는 원리적으로 0바이트 추출된다.** (`grep -c "ToUnicode\|Identity-H" bin/s9` → **0**)
2. **ToUnicode CMap 미적용** — 서브셋 폰트의 glyph id → 유니코드 역매핑이 없다. docstring이 "완전하지 않을 수 있으나"라 적은 것보다 훨씬 나쁘다: 완전히 실패한다.
3. **FlateDecode 전용** — 2834행 `zlib.decompress` 실패 시 `pass`로 원본 바이트를 그대로 스캔. LZWDecode/ASCII85/RunLength는 쓰레기를 뱉는다.
4. **`stream…endstream` 비탐욕 매칭**(2832행) — 바이너리 스트림이 `endstream` 바이트열을 포함하면 그 뒤 본문 전체가 잘린다.
5. **첫 8MB만 읽음**(2828행 `f.read(8*1024*1024)`) — 상한은 30MB인데 22MB는 아예 안 읽는다.

추가: 페이지 순서 무보장(스트림 등장 순), 스캔 이미지 PDF는 OCR 부재로 0바이트(자명), `limit=8000`자 하드컷.
