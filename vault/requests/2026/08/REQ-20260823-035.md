## Notes

### 2026-08-23T16:17:01+09:00 response (by nicehugepark)

문서 스트림 live 판정 수정: 기존 req_stream은 REQ 뒤에 다른 user 턴이 있으면 구간을 닫아 live=False로 판정 → 세션 중간에 생긴 요청(REQ-20260823-028 등)은 진행 중이어도 실시간 갱신 안 됨. 수정: binding.last_req == 이 REQ면(=세션 현재 활성 요청) 구간 끝(end)을 열어 live=True. 시작 매칭 실패 시에도 활성 REQ면 마지막 user 턴부터 끝까지를 구간으로. 검증: 활성 REQ-20260823-035 live=True(7 events), 비활성 REQ-20260823-028 live=False(81 events, 정상 구분).

### 2026-08-23T16:17:19+09:00 response (by nicehugepark)

수정 확인 — **활성 REQ(035, 지금 작업 중)는 `live: True`**로 실시간 갱신되고, 비활성 REQ(028, 이미 지나간 요청)는 `live: False`로 올바르게 구분됩니다. 즉 사용자가 "지금 작업 중인 요청"의 문서 상세를 열면 스트림이 실시간으로 흐릅니다.

다만 정직하게 짚을 점: 사용자가 REQ-20260823-028을 열었던 시점엔 REQ-20260823-028이 활성이었는데도 live가 아니었습니다. 그 근본 원인은 REQ-20260823-028이 이 긴 세션 중간에 생겨 그 뒤 다른 요청들의 user 턴이 이미 있었기 때문이고, 이번 수정으로 "현재 활성 REQ면 뒤 턴 무시하고 live"가 되어 해결됩니다. REQ를 마무리합니다.
