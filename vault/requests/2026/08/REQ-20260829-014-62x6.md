## Original

deep-diver 규명(REQ-20260829-013)의 후반부. 서브에이전트의 말은 리드 세션 transcript 에 한 줄도 없고 <sessionUUID>/subagents/agent-<agentId>.jsonl 에 isSidechain:true 로 들어간다. /api/stream 의 parse_stream_file(bin/s9:11442)이 리드 파일 하나만 열어 스폰 두 줄과 완료 통지 사이가 통째로 0이다. isSidechain 분기(bin/s9:11464)와 화면의 사이드체인 렌더(web/index.html:7478)는 옛 레이아웃 유물로 지금은 도달 불가능한 죽은 코드다.

가장 무거운 지점: offset 이 단일 파일 바이트값이라 두 파일을 timestamp 로 머지하면 API 계약이 바뀐다. session_agents_map 이 이미 output 경로를 안다.

013 본체는 '살아 있는지 보이는가'(라벨·사라짐·스피너·초 갱신)를 맡고, 이 문서가 '무슨 말을 하는지 보이는가'를 맡는다.

### 적용 완료 (무인 작업자, 세션 e6f62b91)

**원인.** 서브에이전트의 말은 리드 transcript 에 한 줄도 없다 — `<sessionUUID>/subagents/agent-<id>.jsonl` 에 따로 쌓인다. 터미널 판은 `/api/stream` 하나만 읽으므로 스폰 두 줄과 완료 통지 사이가 통째로 0이었다. `isSidechain` 분기(bin/s9)와 화면의 사이드체인 렌더는 옛 레이아웃 유물이라 도달 불가능한 죽은 코드였다.

**고친 자리 — 화면(web/index.html)뿐이다.** 서버 offset 은 파일 하나의 바이트값이라 두 파일을 서버에서 머지하면 /api/stream 계약이 바뀐다(문서가 짚은 그 지점). 그래서 원천마다 자기 offset 을 들고 **화면이 시각으로만 겹친다** — 읽을 길은 이미 있었다(`/api/agents`·`/api/agentstream`).

- 순수 블록 `subagent merge core (pure)` 신설: `subFollowPlan`(틱마다 물어볼 목록·증분 offset·내려간 뒤 tail 한 번), `subBackfillPlan`(붙는 순간엔 끝난 에이전트도 포함), `subTag`(agent·atype·aid), `subCap`(에이전트당 200줄 상한), `subOrder`(안정 정렬).
- `termAttach`: `/api/agents` 를 함께 부르고 각 에이전트 파일을 읽어 리드 이력·수신함 로그와 한 벌로 정렬해 그린다. `T.subs` 는 세션 교체 때 비운다.
- 2.5초 `subTick`: 스트립이 아는 에이전트마다 자기 offset 으로 증분만 받아 같은 버퍼에 넣는다. `termScheduleFlush` 가 배치를 시각 순으로 겹친다.
- 죽은 사이드체인 렌더를 되살려 씀: 요약선이 `agent` 익명 대신 종류(backend-developer 등)를 말하고, 시각 도장은 미리보기에서 뺐으며(REQ-013 과 같은 규칙), 도구 줄은 리드와 같은 `ccToolSummary` 를 쓴다.

**정렬 열쇠 주의.** 열쇠는 표시 시각 `ts` 다. 섞이는 원천이 셋인데(수신함 채팅·리드·에이전트) 채팅 줄에는 원본 UTC(`at`)가 없어, UTC 를 우선 열쇠로 삼으면 채팅 줄이 9시간 어긋난 자리로 끌려간다. 시험 `test_the_chat_line_is_not_dragged_nine_hours` 가 이걸 잠근다.

**검증.** `tests/test_subagent_flow.py` 신설 27건 통과(순수 로직 node 실행 · 화면 소스 계약 · 스크립트 전체 파싱 · 실서버 통합 — 픽스처로 10분 침묵 구간을 만들고 두 API 로 그 구간이 메워지는지, 두 번째 물음엔 새 줄이 없는지 확인). 전체 스위트 2051건 OK(skipped 3). 실화면: `scratchpad/term-014d.png` (18:04 리드 메시지와 18:27 리드 메시지 사이가 ⚙ backend-developer 줄로 채워짐, 이전엔 그 사이가 빈칸), `scratchpad/term-014e.png`.

**남은 것 — bin/s9 범위라 제안만 남긴다(이 세션의 수정 범위는 web/·vault/·tests/).**
1. `session_agents_map` 은 Agent 도구의 tool_result 에서 `agentId`·`output_file` 을 읽는다. 그래서 **워크플로(Workflow) 안에서 도는 에이전트**(`subagents/workflows/wf_*/agent-*.jsonl`)와 tool_result 가 아직 안 온 포어그라운드 에이전트는 목록에 없고, 따라서 이 판에도 안 흐른다. 실측: 세션 911949e0 이 18:14~18:17 에 워크플로 에이전트 둘을 돌리는 동안 `/api/agents` 는 architect 하나만 답했다. 서버가 세션 디렉토리의 `subagents/**` 를 훑어 보완하면 그 구멍이 닫힌다.
2. `/api/agentstream` 은 폴링뿐이다(SSE 없음). 에이전트 줄만 2.5초 늦게 오는데, 리드 줄과 같은 즉시성을 원하면 SSE 를 열거나 `/api/stream/sse` 가 에이전트 델타를 함께 실어야 한다.
