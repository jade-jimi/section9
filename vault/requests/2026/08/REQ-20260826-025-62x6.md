## Original

보드 화면의 반려 버튼은 되는데 문서 본문에서는 클릭해도 아무 반응이 없다 (2026-08-26 사용자 지적, REQ-20260826-023 반려 사유에 동봉).

원인: web/index.html 의 document click 핸들러 하나에 `[data-goto]` 분기가 두 개 있다. 앞선 분기(5410행)는 data-goto 를 **탭 이름**으로 보고 header 탭을 찾아 클릭한다 — 못 찾으면 그냥 `return` 한다. 문서 본문의 전이 버튼은 `data-goto="REQ-...|in-progress|review"` 형식이라 탭을 못 찾고 거기서 삼켜진다. 실제 전이 핸들러(5447행)는 **같은 리스너 안 아래쪽**이라 도달하지 못한다.

보드의 승인/반려는 data-approve/data-reject 라 이 경로를 타지 않아 멀쩡했다 — 그래서 한쪽만 깨져 보였다.

## Notes

### 2026-08-26T21:43:14+09:00 response (by sjpark1)

고쳤다.

무엇이 문제였나 — 문서를 열면 제목 아래에 `→ blocked / → cancelled / → done / → review` 버튼이 있다. 이걸 누르면 아무 일도 일어나지 않았다. 보드 화면의 승인/반려 버튼은 멀쩡했다.

왜 그랬나 — 두 종류의 버튼이 같은 표시(data-goto)를 쓰고 있었다. 하나는 "다른 탭으로 이동", 하나는 "상태 바꾸기"다. 클릭을 처리하는 코드가 먼저 "탭으로 이동"으로 해석해보고, 해당하는 탭이 없으면 **거기서 그냥 멈춰버렸다**. 그래서 상태 바꾸기 코드까지 도달하지 못했다. 보드의 승인/반려는 다른 표시를 써서 이 경로를 타지 않았고, 그래서 한쪽만 고장 나 보였다.

무엇을 바꿨나 — 탭 이동 쪽은 이제 탭 이름 형태의 값만 가져간다. 상태 바꾸기 값(문서번호가 섞인 형태)은 손대지 않고 넘긴다. 한 줄 조건 추가다.

검증 — 코드 계약 테스트 4건(tests/test_goto_dispatch.py) 추가. 실제 클릭은 헤드리스로 흉내낼 수 없어 확인 못 했다. 문서 화면에 버튼이 제대로 그려지는 것까지는 캡처로 봤다(scratchpad/goto-docbody.png). 대시보드는 재기동해 새 코드로 돌고 있다.
