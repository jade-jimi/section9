### 원인 (실측으로 확정 — 추측 아님)

리드 소견의 두 후보(013 키보드 접근 / 010 오버플로) **둘 다 아니다.** 오늘 회귀도
아니다. 범인은 목록 머리 `.grp` 의 **sticky 오프셋**이다.

    .doclist .grp{ position:sticky; top:var(--tbh,30px); background:var(--panel) }

`--tbh` 는 Docs 가 렌더 직후 **타입바 실측 높이**로 채운다(renderDocs). Settings
목록에는 타입바가 없으니 변수도 없고, 폴백 `30px` 이 그대로 산다.

**sticky 는 위쪽 문턱보다 위에 있는 상자를 아래로 밀어낸다.** 스크롤이 0일 때
`.grp` 의 제자리는 컨테이너 맨 위(0px)인데 문턱이 30px 이라, 머리가 30px 아래로
내려간다. 그런데 sticky 는 **자리를 비워 두지 않는다** — 내려간 머리가 불투명한
`background:var(--panel)` 로 바로 다음 행의 **첫 줄(제목)을 덮는다.** Docs 에서
멀쩡한 이유는 타입바가 위쪽 30px 을 차지해 `.grp` 의 제자리가 이미 30px 이라
밀릴 곳이 없기 때문이다.

실측(브라우저 CDP, `.grp` 아랫변 − 제목 윗변 = 가려진 높이):

    ledger +21px · calm +19px · soft +21px · glass +21px · terminal +21px
    grid +24px · slate +21px · cobalt +21px · field +21px · cork +21px

**스킨 10종 전부** 잘린다 — calm 만의 문제가 아니었다. Stream 탭의 빈 상태 줄
(`no streams …`)도 같은 자리에 있어 같이 밀려 있었다.

### 고쳤다 — 목록 머리의 sticky 문턱을 0으로, 오프셋은 타입바가 있을 때만

**원인은 오늘 커밋 둘(013·010)이 아니었다.** 리드 소견의 두 후보를 실측으로 지우고
범인을 확정했다: 목록 머리 `.grp` 의 sticky 문턱이다.

    .doclist .grp{position:sticky; top:var(--tbh,30px); background:var(--panel)}

`--tbh` 는 Docs 가 렌더 직후 타입바를 실측해 넣는다. Settings 목록에는 타입바가
없으니 변수도 없고 폴백 `30px` 이 산다. **sticky 는 문턱보다 위에 있는 상자를 아래로
밀어내면서 자리는 비워 두지 않는다** — 머리가 30px 내려앉아 불투명한 배경으로 첫 행의
제목 줄을 덮었다. 스킨 10종 실측 가림 +19~+24px(**calm 만이 아니라 전종**).
Docs 가 멀쩡했던 건 타입바가 위쪽을 차지해 머리의 제자리가 이미 그만큼이었기 때문이다.

**처방 — JS 가 변수를 채워 주기를 기다리지 않는다.**

    .doclist .grp{… top:0 …}
    .doclist .typebar ~ .grp{top:var(--tbh,30px)}

오프셋을 기본값에서 빼고 **선행 타입바를 요구하는 선택자**로 옮겼다. 조건을 선택자에
적어 두면 이 위젯을 타입바 없이 재사용하는 자리가 스스로 옳게 선다 — 지금 그런 자리가
둘(Settings 설정 머리 · Stream 빈 상태 줄 `no streams …`)이고, 셋째가 생겨도 안전하다.
`--tbh` 를 Settings 에서 0으로 채워 주는 우회도 가능했지만, 그건 같은 함정을 다음
재사용자에게 그대로 남긴다.

**검증 (실브라우저 CDP 실측 — 눈대중 아님)**
