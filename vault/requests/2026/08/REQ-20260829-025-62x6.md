### 2026-08-29T22:40:14+09:00 tdd (by nicehugepark)

문서를 치우는 길 — 3단 모형(보관 / 삭제 / 소거)의 시나리오.

되돌릴 수 있는 순서로 층을 나눈다. **보관**은 파일을 그대로 두고 목록에서만 내린다. **삭제**는 같은 폴더의 .trash 로 옮긴다(번호는 계속 물고 있어 재발번이 없다). **소거**는 .trash 안의 것만 지우고, 그 자리에 번호만 남긴 묘비를 세운다 — 지운 번호가 다른 문서로 다시 나가는 사고를 막던 그 장치를 소거가 뚫으면 안 된다.

- [ ] S1 s9 archive 문서 — frontmatter 에 archived 시각이 서고 History 에 한 줄이 남는다
- [ ] S2 보관된 문서는 s9 ls 기본 목록에서 빠지고 s9 ls --archived 에서만 보인다 (카탈로그 행에는 archived 필드로 남는다)
- [ ] S3 s9 unarchive 문서 — archived 가 지워지고 목록에 돌아온다
- [ ] S4 s9 rm 문서 여러 건 — 한 번에 .trash 로, 카탈로그에서 사라진다
- [ ] S5 s9 trash — 휴지통 목록에 id·제목·버린 시각이 나온다
- [ ] S6 s9 restore 문서 — 원래 자리로 돌아오고 카탈로그에 다시 뜬다 (첨부도 함께)
- [ ] S7 s9 purge 문서 --yes — .trash 의 파일이 실제로 사라진다. --yes 없으면 거부, 휴지통에 없는 살아 있는 문서도 거부
- [ ] S8 소거 뒤에도 그 번호는 재발급되지 않는다 (.trash/purged 묘비)
- [ ] S9 HTTP — POST /api/docs/archive·rm·restore·purge 와 GET /api/trash 가 CLI 와 같은 함수를 지난다
- [ ] S10 화면 — 문서 뷰어에 보관/삭제 손잡이, 목록에 고르기(다중 선택)와 묶음 처리 띠, 휴지통·보관함 보기에서 복원/완전 삭제
