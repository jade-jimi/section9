### 반려 재작업 결과 (auto 모드 반영)

**원인 규명**: 이전 구현이 안내한 `--permission-mode acceptEdits`는 파일 편집만 자동 승인하고 Bash 등은 계속 사람이 승인해야 한다 — "이걸 사람이 또 리뷰해야하나"의 원인. 현행 claude CLI에는 `--permission-mode auto`(auto 모드 분류기)가 별도로 존재하며, 반려가 요구한 모드는 이것이다.

**적용 (즉시 유효)**
1. `s9 user config sjpark1 s9code_args "--permission-mode auto"` 설정 — 이제 `s9 code`만 치면 claude가 auto 모드로 뜬다. 수동 인자 불필요.
2. tests/test_s9_code_args.py 에 G5 추가: s9code_args auto 설정 → exec 인자 `["claude","--permission-mode","auto",...]` 검증.

**검증**: python3 tests/ test_s9_code_args → 5/5 OK. 전체 스위트 81/81 OK.

**"직접 실행과 완전 동일" 분석**: cmd_code는 os.chdir(~/section9) 후 execvp로 claude를 대체 실행한다 — tty·환경변수·cwd·프로젝트 설정 모두 직접 실행과 동일하며, 유일한 차이였던 permission 모드가 이번 설정으로 auto가 됐다.

**남은 제안**: 무설정 기본값 auto는 bin/s9 수정이라 무인 봉투 범위(web/·vault/·tests/) 밖 — 별도 patch note 참조.

### bin/s9 패치 제안 — 무설정 기본 auto 모드 (리드 적용 대상)

무인 봉투가 bin/ 수정을 금지해 제안으로 남긴다. cmd_code의 cmd 조립부(현재 `cmd = ["claude"] + extra + (args.claude_args or [])` 한 줄)를 아래로 교체하면, s9code_args 설정이 없는 계정도 기본 auto 모드가 된다(사람 재승인 제거). 모드 관련 인자가 이미 있으면 개입하지 않아 config·명령행 우선순위는 유지된다.

```python
argv = extra + (args.claude_args or [])
if not any(a in ("--permission-mode", "--dangerously-skip-permissions") for a in argv):
    argv = ["--permission-mode", "auto"] + argv  # 무설정 기본 = auto (REQ-20260824-036)
cmd = ["claude"] + argv
```

적용 시 tests/test_s9_code_args.py 의 G2(다른 값 우선)·G5(auto)는 그대로 통과하고, "무설정 → --permission-mode auto 포함" 케이스를 G6으로 추가하면 된다. 적용 후에는 sjpark1의 s9code_args 설정은 중복이므로 `s9 user config sjpark1 s9code_args ""` 로 비워도 된다.
