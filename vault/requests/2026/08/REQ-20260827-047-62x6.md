## Original

사용자 질문: "이력을 지우고 옮기는건 할 수 없나?"

## Notes

### 2026-08-27T20:39:39+09:00 analysis (by sjpark1)

**할 수 있다. 그리고 지금이 가장 싸다 — 다만 완전히 지워지지는 않는다.**

**지금 상태 (실측)**

    원격 main       c16d407  ← 스트림을 담은 커밋은 **이것 하나뿐**
    로컬 앞선 커밋   07ed0d7 · 230788a  (아직 안 올라감, 스트림 안 건드림)
    .git 크기       122MB
    푸시 시각        약 20:21

**왜 지금이 싼가**: 스트림이 들어간 커밋이 **하나**고, 그게 원격의 tip 이다.
뒤에 쌓인 것도 아직 원격에 없다. 나중에 커밋이 쌓이면 재작성 범위가 넓어지고,
그때는 남이 clone 했을 확률도 올라간다.

**절차 (되돌릴 수 없는 쪽으로만 간다 — 실행 전에 백업 브랜치를 남긴다)**

    1. git branch backup-before-rewrite      # 되돌릴 자리
    2. git filter-branch --index-filter \
         'git rm -r --cached --ignore-unmatch streams' -- c16d407^..HEAD
       (filter-repo 는 이 머신에 없다. 범위가 커밋 3개라 filter-branch 로 충분하다)
    3. .gitignore 에 streams/ 를 되살린다 — 다시 안 들어오게
    4. git push --force origin main
    5. 로컬 streams/ 는 그대로 둔다 (파일은 안 지운다) — 위치 이동은 아래 별건

**정직하게: "지웠다"는 절반만 참이다**
- 원격에서 **참조는 끊기지만**, GitHub 은 unreachable 객체를 한동안 보관한다.
  SHA 를 아는 사람은 그 사이 API 로 꺼낼 수 있다. 완전 삭제는 GitHub 지원에
  요청해야 한다.
- 20:21~지금 사이에 clone·fork 한 사람이 있으면 그쪽에는 남는다. 이 리포를
  지켜보는 사람이 없다면 사실상 0 이지만, **0 이라고 말할 수는 없다.**
- 재작성하면 c16d407 이후 **모든 커밋 해시가 바뀐다.** 다른 머신에 클론이 있으면
  그쪽은 강제로 맞춰야 한다(지금은 이 머신뿐이라 문제 없다).

**실행에 필요한 것**: `git push --force` — 내가 못 한다(같은 게이트). 사용자가
한 줄 실행하거나 권한을 열어야 한다. 재작성 자체(1~3)는 내가 할 수 있다.

**옮기기(사용자별 보관)는 이력 재작성과 같이 하는 것이 맞다.** 따로 하면 옮긴
경로가 또 한 번 이력에 실린다. 재작성으로 streams 를 걷어낸 뒤,
`users/<u>/streams/` 로 옮기고 그 자리를 처음부터 ignore 로 두면 이력에 한 번도
안 실린다.

**리드 의견**: 하는 쪽을 권한다. 158MB 가 122MB 의 대부분이고, 앞으로 매주 그만큼
불어난다. 되돌릴 기회가 지금밖에 없다. 다만 **완전 삭제가 아니라는 점**을 알고
결정해야 한다.
