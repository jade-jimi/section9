## Original

깃헙에 푸시 여부에 대해서 옵션 설정을 바꿨는데 어디서 하는거지?

## Notes

### 2026-09-01T18:43:46+09:00 answer (agent: lead:claude-opus-5, by nicehugepark)

`[2026-09-01 18:43:46 KST - lead]`

찾아봤습니다. **section9에는 "깃헙에 푸시할지 말지" 스위치가 없습니다.** 화면(Settings)에도, CLI에도 없습니다. 인접한 설정이 셋 있는데, 바꾸신 게 이 중 하나일 겁니다.

**1. `auto_resume_gh` — 무인 작업자에게 `gh`(깃헙 CLI) 권한을 줄지** ← 지금 `on`

지금 계정 설정에 켜져 있습니다. 뜻은 "사람이 없는 자리에서 도는 작업자가 깃헙 계정 권한을 써도 좋다"입니다(`gh api` 하나로 저장소 설정 대부분을 바꿀 수 있으니 가벼운 스위치가 아닙니다). 푸시 자체를 막거나 여는 값은 아닙니다.

바꾸는 곳은 **터미널뿐입니다** — 대시보드 Settings → 내 계정 아래쪽 `기타: {...}` 줄에 값이 *보이기만* 하고 편집칸은 없습니다.

```bash
cd ~/section9
bin/s9 user config nicehugepark auto_resume_gh off    # 끄기
bin/s9 user config nicehugepark auto_resume_gh on     # 켜기
bin/s9 user config nicehugepark                        # 현재 값 전부 보기
```
끌 때는 빈 값이 아니라 `off`를 넣으세요. 바꾸면 다음에 뜨는 무인 작업자부터 적용되고, 이미 돌고 있는 작업자에는 영향이 없습니다.

**2. `bin/s9-git-gate` — git 명령 문지기** (`~/.claude/settings.json`의 훅)

`stash drop`처럼 남의 작업을 삼키는 것만 막고, `commit`·`push`는 그냥 통과시킵니다. 푸시 여부를 여기서 정하지는 않습니다.

**3. "main에 바로 푸시" 규칙** — 이건 설정이 아니라 제 작업 규율로 기억해 둔 것입니다(리포 주인이라 PR 없이 main 직접 푸시 승인). 바꾸시려면 설정 파일이 아니라 말씀만 주시면 됩니다.

혹시 바꾸신 게 클로드 코드 쪽(`/config`)이나 깃헙 저장소 설정이었다면 그건 이 저장소 밖이라 제가 못 찾습니다 — 어떤 화면에서 무슨 문구였는지 한 조각만 알려 주시면 정확히 짚어 드리겠습니다.

(팝업 잘림 건은 회귀 스위트가 아직 돌고 있습니다. 끝나면 이어서 보고하겠습니다.)
