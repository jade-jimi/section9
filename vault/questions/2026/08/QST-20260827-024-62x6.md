## Original

2번 했어도 상관없지? 어차피 이 하네스는 깃헙을 통해 동기화를 한다. 푸시를 스스로 못하면 말이 안되는 시스템이 되는거다.

## Notes

### 2026-08-27T21:17:19+09:00 answer (agent: lead:claude-opus-5, by nicehugepark)

`[2026-08-27 21:17:19 KST - lead]`

**2번(Project settings)이었으면 문제가 있었다.** 그 파일은 git 에 올라가고, **이 리포는 공개다.** 클론하는 모든 사람의 Claude Code 에 `Bash(git push:*)` 가 자동 허용으로 붙는다 — 그것도 그 사람 자신의 리포에까지. 3번(User)에 넣으신 게 맞다.

**다만 지적하신 논지는 옳다.** 이 하네스가 깃헙으로 동기화하는 시스템이라면 **에이전트가 푸시할 수 있어야 정상**이고, 그게 머신마다 우연히 켜지는 건 설계가 아니다. 그래서 이렇게 갈라야 한다:

| | |
|---|---|
| **공개 업스트림**(이 리포) | 넣지 않는다. 낯선 사람이 클론했다고 푸시 권한을 받으면 안 된다 |
| **사설 인스턴스**(팀 작업 리포) | `.claude/settings.json` 에 넣는다. 그 팀이 원하는 것이고 사설이다 |

036 에서 이미 정한 공개/사설 경계와 정확히 같은 선이다. `s9-install` 이 인스턴스에서 이걸 넣어 주게 하는 게 맞다 — 우연에 맡기지 않고. 045(설정 미러)와 함께 다루겠다.

### 푸시 — Claude 게이트는 통과했다. 이번엔 GitHub 이다

```
remote: GH006: Cannot force-push to this branch
```

`main` 에 **강제 푸시 금지**가 걸려 있다. `gh` 로 그 항목만 잠깐 켜고 → 밀고 → 다시 끌 수 있다. **다만 그 보호는 기본값이 아니라 직접 거신 것이라**(PR 승인 1건 + 강제 푸시 금지 + 삭제 금지) 제 판단으로 풀지 않는다. **"풀어도 된다"만 하시면** 켜고→푸시→끄고, 끈 것까지 확인해 보고하겠다.

### 보내신 이미지

**그래프 자체는 정상이다** — 제가 같은 화면을 찍어 보니 잘 그려진다. 보내신 건 필터가 걸린 상태고, 안내문이 뜬 것도 설계대로다.

**문제는 그 안내가 원인을 안 짚는다는 것이다.** 진짜 원인은 **헤더의 `type: question` 필터**인데, 안내는 "27건이 전부 질문인데 그 종류를 꺼 뒀다"까지만 말한다. 되돌릴 자리를 안 알려주니 고장으로 읽힌다. 그리고 좁은 창에서 **오른쪽이 잘린다** — 범례 줄과 오른쪽 레일이 화면 밖으로 나간다.

designer 에게 넘겼다. 원인을 실측으로 확정하고, 안내가 그 필터를 직접 가리키게 하고, 폭별로 확인하라고 보냈다.

### 정리 하나

`git add -A` 로 커밋하면서 **무인 작업자가 쓰던 파일을 제 커밋에 쓸어 담았다**(`tests/test_streams_untracked.py`). 잃은 건 없지만, 제가 남한테 경고하던 그 실수를 제가 했다. 앞으로 워커가 도는 동안은 경로를 지정해서만 담겠다.
