## Original

024(시각 타임존)은 왜 세션 재시작해야 바뀌는거지?

## Notes

### 2026-08-28T16:33:01+09:00 answer (agent: lead:claude-opus-5, by nicehugepark)

`[2026-08-28 16:33:01 KST - lead]`

제가 틀렸습니다. **재시작 필요 없습니다 — 이미 적용돼 있습니다.**

훅은 매 턴 새 프로세스로 `bin/s9-audit-prompt` 를 읽어 실행합니다. 그래서 파일을 고치는 즉시 다음 프롬프트부터 새 코드가 돕니다. 재시작이 필요한 건 훅 **등록**(settings.json)이 바뀔 때뿐이고, 이번엔 등록이 아니라 내용만 바뀌었습니다.

지금 이 턴에 주입된 값이 `KST` 인 건 설정이 `Asia/Seoul` 이라서 그렇습니다 — 바뀐 코드가 설정을 읽어 낸 결과입니다. 방금 확인했습니다:

```
설정 그대로: ◈ 현재 시각 2026-08-28 16:32:42 KST
베를린으로 : ◈ 현재 시각 2026-08-28 09:32:42 CEST
```

`s9 user config nicehugepark timezone Europe/Berlin` 으로 바꾸시면 **다음 프롬프트부터** 그 시간대로 나옵니다. 024 문서 노트의 그 마지막 줄은 틀렸으니 지우겠습니다.

**026(첨부 폴더)** 도 접수했고, 물으신 대로 **중복 가능성이 실재합니다.** 실측한 것:

- 접미사 없는 첨부 폴더가 5개 있습니다 (`REQ-20260825-012`, `-029`, `REQ-20260827-072-62x6`, `REQ-20260828-006-62x6`, `-007`)
- 원인은 `doc_asset_dir()` 이 **부른 사람이 넘긴 문자열을 그대로** 폴더 이름으로 쓰는 것입니다. `locate()` 는 짧은 id 도 찾아 주니 문서는 제대로 찾고 폴더만 짧게 만들어집니다
- 그래서 **한 문서의 첨부가 두 폴더로 갈립니다.** 007 은 짧은 폴더에 7개, 정식 폴더에 3개가 따로 있습니다
- 정식 id 로 물으면 못 찾습니다: `?doc=REQ-20260828-007-62x6` → **200**, `?doc=REQ-20260828-007-62x6` → **404**. 지금 화면이 안 깨지는 건 프런트가 본문에 적힌 경로에서 id 를 그대로 떼어 쓰기 때문이지 폴더가 맞아서가 아닙니다
- 그리고 물으신 그것 — 접미사는 **인스턴스 식별자**라, 짧은 이름은 그걸 버립니다. 다른 인스턴스의 `REQ-20260828-007-ab12` 와 이 저장소의 `-62x6` 이 같은 폴더 이름으로 겹칩니다

고치겠습니다: 폴더 이름을 **문서의 정식 id** 로 못박고, 이미 갈린 5개를 합치면서 본문 참조도 같이 고쳐 쓰겠습니다(참조만 두고 파일을 옮기면 화면이 깨집니다).
