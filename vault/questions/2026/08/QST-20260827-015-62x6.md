REQ-20260827-036 판정을 해야하는데, 생각해보니 stream은 개인 설정으로 선택사항으로 써도 되지 않을까? 모든 문서에서 스트림이 저 스트림을 사용하는건가? 문서 만으로 하네스 기능과 성능, 품질이 유지가 된다면 굳이 스트림이 필요가 없긴한데, 그래서 대화기록이 있어야 계정을 바꾸든 머신을 바꾸든 이어서 작업이 가능한게 맞는거지? 그런데 문서만으로도 그게 되는거면 스트림 기능의 존재 이유가 없어지기도 하고 말이야. 그래서 개인이 사용할지말지와 스트림은 개인별, 하네스 계정인 user 별로 관리되는게 어떤가? 그래서 개인설정에서 끌 수도 있고 켤 수도 있고. 어떻게 생각해?

좋은 질문이다. 코드를 재 보고 답한다.

**① "모든 문서에서 저 스트림을 쓰는가" — 아니다.** `streams/` 를 읽는 자리는 셋뿐이다:

```
1. live 초록점 판정의 보조 신호   (주 신호는 바인딩의 transcript_path)
2. 대시보드 Stream 탭
3. s9 resume — 다른 머신·계정에서 같은 대화 되살리기
```

digest·카탈로그·검색·상태 전이 같은 **문서 쪽 기능은 스트림을 전혀 안 쓴다.** 하네스 본체(프롬프트 → REQ → 상태 → 보고)는 스트림 없이 그대로 돈다.

**② "대화 기록이 있어야 계정·머신을 바꿔 이어서 작업이 되는 게 맞나" — 맞다. 그게 스트림의 유일한 대체 불가 역할이다.** `s9 resume` 은 미러를 `~/.claude/projects/…` 로 **복원한 뒤** `claude --resume` 을 띄운다. Claude Code 는 그 원본 파일을 요구하므로 문서로는 못 만든다.

**③ 그래서 두 가지를 갈라야 한다:**

| | |
|---|---|
| **문서** | 무엇을 왜 했는가 → 새 세션이 읽고 **이어서 일한다** |
| **스트림** | 그 대화 자체 → **같은 대화를 그대로 되살린다** |

"이어서 일하기"는 문서로 된다. "같은 대화 되살리기"는 스트림이라야 한다. 후자가 필요 없는 사람에게는 **정말 선택사항이 맞다.**

### 제안에 동의한다. 다만 더 큰 지렛대는 on/off 가 아니다

```
전체 50개 158MB  ·  최근 1일 11개 47MB  ·  3일 33개 136MB  ·  7일 50개 158MB
```

**일주일치가 전부다.** 158MB 는 오래 쌓여서가 아니라 **하루 47MB씩 쌓이는데 아무도 안 지워서**다. 끄면 0이 되지만, 켜 둔 사람은 한 달 뒤 700MB 다. on/off 만으로는 켜 둔 쪽 문제가 안 풀린다.

**제안하는 모양 셋** (REQ-20260827-042-62x6 로 등록했다):
1. **`stream_mirror` 사용자 설정, 기본 켜짐.** 끄면 `s9 resume` 이 안 되는데, 그 능력을 말없이 잃는 게 디스크보다 나쁘다. 끌 때 그 사실을 화면에 적는다.
2. **보관을 사용자별로** (`users/<u>/streams/`). 이 시스템의 다른 것(가시성·설정·비밀)이 전부 사용자 단위인데 남의 대화 원문만 공용 자리에 섞여 있는 지금 모양이 어색하다.
3. **보존 기간** — 기본 N일 지난 미러 정리, 진행 중 REQ 가 붙들고 있는 세션은 예외. **이게 158MB 를 실제로 줄이는 유일한 손잡이다.**

**036 은 이것과 무관하게 지금 판정하셔도 된다.** 어느 쪽으로 정하든 오늘의 157MB 를 공개 리포에 올리지 않는다는 판단은 그대로다.
