## Original

REQ-20260831-002 진단 중 확립. 대시보드가 타임아웃일 때 서버 수리를 거듭해도 안 나으면 회선을 의심하라.

## 판별 3단계 (s9 무관, 표준 파이썬만)
1. **원시 루프백 전송률**: 한 프로세스에서 listen→connect→4MB sendall/recv 로 초당 바이트를 잰다. 정상 GB/s. 실측 128KB/s 면 회선 붕괴다. listen 직후 connect 가 거절되면 그것도 신호다.
2. **nstat 카운터**: `nstat -az | grep -iE 'retrans|fail|drop'` — 루프백만 쓰는데 TcpAttemptFails·TCPLossUndo·SlowStartRetrans 가 쌓이면 가상 NIC/커널 상태 손상.
3. **faulthandler 스택**: 서버를 PYTHONFAULTHANDLER=1 로 띄우고 느린 요청 중 SIGABRT — 핸들러가 이미 응답을 다 쓰고 readinto(다음 요청 대기)에 있으면 서버는 무죄, 시간은 회선에서 샌다.

## 함정 (실측)
- ps 의 %CPU 는 수명 평균이라 순간 포화를 감춘다. 벽시계·CPU delta(/proc/pid/stat utime)로 재라.
- WSL2 루프백은 동시 SYN 을 ~10개에서 자른다(DOC-20260827-004) — 벤치 클라이언트는 램프업+지터 없이는 herd 아티팩트를 잰다.
- 이 상태는 2026-08-25 포트 고갈 사고(REQ-20260825-102)와 같은 계열 — 회복은 wsl --shutdown 또는 Windows 재부팅.
