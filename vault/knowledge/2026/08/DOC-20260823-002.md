## Original

## 검증: 다른 머신에서 세션 resume 가능한가?

**결론: 가능하다 (실증 완료).** 사용자 가설("section9이 jsonl을 저장했다면 resume도 가능")이 정확했다.

## resume 메커니즘 (실측)
- `claude -p "<prompt>" --resume <SID>` 는 `~/.claude/projects/<cwd-key>/<SID>.jsonl` 을 읽어 이전 맥락을 이어간다.
- cwd-key = cwd 경로의 `/` 와 `.` 을 모두 `-` 로 치환 (예: /tmp/tmp.abc → -tmp-tmp-abc).
- SID = 전체 UUID (예: 18093278-22fa-413c-b6f4-f33d6924c8c1). 8자 축약 아님.
- resume은 SID로 파일을 찾으므로 cwd가 달라도 동작(같은 머신 내). 파일만 정규 위치에 있으면 됨.

## 크로스머신 실증 (3단계)
1. 세션 생성(계산: 2 → +10=12 → ×100=1200), 파일을 section9 streams에 전체SID 이름으로 백업.
2. 원본 세션 파일 완전 삭제 = "m2엔 세션 없음" 상태 재현.
3. 미러 파일만 ~/.claude/projects/<새 cwd-key>/<SID>.jsonl 로 복원 후 resume → "1200에서 200 빼기" = 1000 정답. 이전 맥락 복원 확인.

## section9의 갭 (수정하면 크로스머신 resume 실현)
- 현재 미러(s9-audit-response의 mirror_transcript)는 파일명을 8자로 잘라 저장(streams/{session8}.jsonl) → resume이 못 찾음.
- 수정안: 미러를 전체 SID 이름으로 저장(streams/{full-SID}.jsonl) + cwd-key도 메타로 보존.
- resume 헬퍼: `s9 resume <SID>` 가 streams의 미러를 ~/.claude/projects/<key>/<SID>.jsonl 로 복원 후 claude --resume 호출.
- 그러면 REQ-20260823-033(대시보드 반려→그 세션 재작업)을 remote-control 없이 `claude -p --resume`으로 구현 가능. 단 옵트인(토큰 비용) 필수.

## 정정
직전 답변에서 "크로스머신 resume 불가"라 한 것은 오류. 미러가 저장돼 있으므로 위치/이름만 맞추면 가능.


## Notes

### 2026-08-23T16:52:33+09:00 correction (by nicehugepark)

[정정] cwd-key 변환 규칙 오류. 본문에 "cwd 경로의 / 와 . 를 모두 - 로 치환"이라 했으나, 실측 재확인 결과 **점(.)은 보존되고 `/`만 `-`로 치환**된다. 예: /tmp/tmp.ojW6VCn23O → -tmp-tmp.ojW6VCn23O (점 유지). 구현 시 `cwd.replace('/','-')`만 사용할 것. [/.] 전체 치환하면 점 포함 경로에서 잘못된 key 생성→resume 실패. (워크플로 설계 검토에서 발견)
