## Original

증상: `s9 shot <url>#terminal` 이 60초 subprocess 타임아웃으로 실패한다. --virtual-time-budget 을 1500ms까지 줄여도 같다.

원인: chrome headless 의 --screenshot 은 네트워크가 idle 이 되어야 찍는다. 대시보드 터미널 탭은 /api/stream SSE 를 열어 두고 끊지 않으므로 idle 이 영원히 오지 않는다. live follow 폴링이 있는 화면도 같은 위험이 있다(폴은 끊겼다 재개하므로 대개 통과한다 — 문제는 끊기지 않는 SSE).

우회(검증된 방법): 검증하려는 것이 렌더 결과라면 실페이지를 띄우지 말고 하네스를 만든다.
1. web/index.html 에서 <style> 전문과 대상 함수 본문을 정규식+중괄호 매칭으로 그대로 추출한다(재타이핑 금지 — 그러면 진짜 코드를 검증하는 게 아니다).
2. 그 CSS + 함수 + 최소 스텁($, esc, 포맷터, 콜백)으로 정적 HTML 을 만들어 web/ 아래 임시 파일로 두고, 이미 떠 있는 서버로 캡처한 뒤 지운다.
3. 상태를 한 페이지에 여러 개 나란히 렌더하면 캡처 1회로 전 상태를 판정할 수 있다(포트 절약).

함정: Python 문자열 안에 `<\\/script>` 를 쓰면 파이썬은 백슬래시를 남겨 HTML 에 `<\\/script>` 가 그대로 나가고 스크립트가 닫히지 않는다 — 페이지가 통째로 죽는데 화면상으론 "빈 컨테이너"로만 보여 원인을 찾기 어렵다. 그냥 `</script>` 로 쓴다.

한계: 실제 폴링·전이·클릭 동작은 이 방법으로 검증되지 않는다. 노트에 미검증 범위를 명시하고 사람 확인을 요청한다.
